## Source material for page text (not images)

To be written up after the gate. Wording must follow the ledger in the internal inventory.

- **API contract (`/api/v1`):**
  - response envelope with `requestId`;
  - named error codes (e.g. `EMAIL_ALREADY_EXISTS`, `STYLE_VERSION_NOT_READY`, `TRAINING_JOB_ALREADY_FINISHED`);
  - camelCase at the boundary;
  - version labels generated by the backend (V1 → V2 → V2-1);
  - style-version status states.

  **Implemented:** the error codes, request IDs and backend-generated version numbers are present in the backend.
  **Designed only:** chat-summary memory and output documents; don't present them as built.
- **Rejected alternatives**, written down before implementation:
  - the backend does not launch GPU instances (SQS + ASG instead);
  - training instances never terminate themselves (they release scale-in protection and the ASG reclaims them);
  - training instances never connect to the database (status goes through an authenticated callback);
  - no RDS Proxy in the MVP;
  - no runtime role may write launch templates.
- **IAM invariants:**

  | Invariant | Status |
  |---|---|
  | `PassRole` exists only in the deploy role | Enforced in Terraform |
  | No runtime role can write launch templates (only the release roles can) | Enforced in Terraform |
  | Runtime roles trust EC2 only | Enforced in Terraform |
  | Training cannot read DB credentials (it reads only its callback-token secret) | Enforced in Terraform |
  | Backend "zombie cleanup" termination scoped by tags | **Designed, not implemented** |
