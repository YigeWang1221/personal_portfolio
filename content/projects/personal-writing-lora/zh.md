## 要解决的问题 {#problem}

通用大模型写出来的是通用腔调。这个平台要学的是每位用户自己的风格：用户上传自己的文字（TXT、Markdown 或 Word 文件），系统基于固定版本的 Qwen2.5-7B-Instruct 基座模型训练个人 LoRA"风格"；之后用户在"项目 + 对话"的工作区里，用当前风格撰写长篇 Markdown，例如文章、社交平台帖子或视频脚本。风格带有版本，用户可以重新训练，同时保留之前的版本。

**如实说明现状：** 平台已在四个仓库中实现，并在本机上端到端跑通，所用的是真实的 PostgreSQL，以及替身形式的云服务和 GPU 服务。它从未部署，也还没有完成过一次真实的训练。本页讲的是设计与工程实现，而不是结果。

## 设计过程 {#design-process}

设计先于代码，整个过程都记录在我的设计笔记里：

1. **线框图与 ER 草图**（2026 年 6 月）确定了信息架构：项目与对话、带版本和状态颜色的风格、草稿面板。
2. **API 契约**（6 月下旬）定义了 `/api/v1` 的响应结构：带请求 ID，使用 `STYLE_VERSION_NOT_READY`、`TRAINING_JOB_ALREADY_FINISHED` 等命名错误码，边界上统一用 camelCase，版本号由后端生成。
3. **"确认版"架构**（7 月初）明确列出了被否决的方案，并定下了 IAM 不变量。
4. **里程碑计划**及带日期的决策日志，随后驱动了实现。

## 当前架构 {#architecture}

- **产品层。** Next.js 应用（严格模式 TypeScript、App Router）调用按 router → service → repository 分层的 FastAPI 后端。PostgreSQL 中有 {{fact:tables}} 张表，由 Alembic 迁移管理，状态字段由 CHECK 约束保护。会话使用 HttpOnly cookie 和不透明令牌，数据库里只保存令牌的 SHA-256 哈希。
- **训练交接。** 提交训练任务时，会在同一个事务里写入一条发件箱（Outbox）记录，再由分发器把它投递到 SQS。GPU worker 认领任务，用 QLoRA 微调，并把适配器发布到 S3。
- **推理层。** 适配器管理服务位于 vLLM 的运行时 LoRA API 之前，负责加载、卸载和缓存适配器，并代理对话与流式请求。
- **契约优先。** worker、后端和推理层之间的接口在实现之前就冻结为 JSON Schema 和 OpenAPI，并附有刻意构造的无效示例，各部分因此可以独立开发和测试。

## 里程碑与决策日志 {#planning}

训练（T0—T5）和推理（W0—W5）各有一份里程碑计划，写明每个里程碑的范围与状态，并附带日期的决策日志。例如：在隐私评审之前，训练样本对的生成只用假数据；适配器管理服务保持单进程，并把安全上限写成明确的配置。Terraform 部分另有一份任务拆解，列出已确认的输入、决策关口和依赖关系，覆盖从状态存储初始化到 AMI 发布集成的全过程。

计划也记录了工作停在哪里：接口契约、数据集构建器、本地 worker 和适配器管理服务已经完成；真实的 GPU 训练已实现但尚未验证；推理和故障演练相关的里程碑还没有开始。

## 关键决策 {#decisions}

| 决策 | 选择 | 取舍 |
|---|---|---|
| 任务交接 | 发件箱表 → SQS，用 S3 条件写入认领任务 | 组件更多；在至少一次投递和进程崩溃时依然安全 |
| 训练算力 | GPU Auto Scaling 组，最小和期望容量均为零，按单实例积压量伸缩 | 有冷启动延迟；没有闲置 GPU 的成本 |
| 推理服务 | 单块 GPU 运行 vLLM，通过适配器管理服务在运行时加载 LoRA | 存在单点故障（第一个版本接受这一点）；多个用户共享一块 GPU |
| 适配器缓存 | 不淘汰使用中适配器的 LRU，每个适配器同一时间只下载一次 | 压力大时可能拒绝加载；绝不会用只加载了一半的适配器提供服务 |
| 接口契约 | 先冻结 schema，再写代码 | 前期投入更多；worker、后端和推理层可以独立开发 |
| 网络成本 | 只用一个 NAT 网关，不用付费的 VPC 端点 | NAT 网关是单点故障；固定成本更低 |

## 至少一次投递下的安全任务交接 {#job-handoff}

SQS 保证的是"至少投递一次"，GPU 实例也可能在任务中途消失。设计同时考虑了这两点：

- **发件箱。** 后端在同一个事务里写入任务和发件箱记录，因此即使在保存任务和投递之间崩溃，任务也不会丢失；重复投递由下游处理。
- **每个风格版本对应唯一的任务身份**，重新排队的任务能被识别为同一个任务。
- **用条件写入认领。** worker 通过在 S3 上的条件写入认领任务，收到同一条消息的两个 worker 不可能都去训练它。
- **租约心跳。** 训练期间，worker 持续延长消息的可见性超时；一旦失去租约就停止工作。
- **最后才删除消息。** 只有后端确认结果之后才删除消息；回调重试会发送完全相同的字节，后端可以据此去重。
- **产物完整性。** 每个适配器写入按用户、任务和产物版本划分的不可变目录，附 manifest，每个文件都有 SHA-256 哈希；`READY` 标记最后写入，适配器以原子方式移入缓存，系统也绝不会悄悄退回到基座模型。

## 缩容至零的训练 {#scale-from-zero}

训练用的 Auto Scaling 组在没有任务时保持零台实例。两条伸缩策略监控一个积压指标（可见消息数 ÷ 运行中实例数），有任务等待时就扩容。每个 worker 只取一条消息，训练期间为自己的实例开启缩容保护，完成后解除保护；积压告警恢复后，伸缩组再缩容。

有几种方案在实现前就被书面否决了：

- 后端从不自己启动 GPU 实例，这件事交给 SQS 和 Auto Scaling 组。
- 训练实例从不自行终止，而是解除保护，由伸缩组回收。
- 训练实例从不连接数据库，状态通过带认证的回调传回。
- 任何运行时角色都不能修改启动模板。

还有两项集成工作未完成：worker 尚未调用终止生命周期动作的完成接口；后端与 worker 之间回调的数据格式和认证方式仍需对齐。

## 多 LoRA 推理 {#serving}

多个用户的风格应当共享一块 GPU，适配器管理服务保证这件事是安全的：

- **每个适配器同一时间最多下载一次**，并发请求会等待这次下载。
- **不淘汰使用中适配器的 LRU 缓存。** 压力大时，它会明确返回 429 或 503 拒绝加载，而不是把其他用户正在使用的适配器淘汰掉。
- **完整性校验。** 加载前会校验 SHA-256 哈希和 `READY` 标记。
- **有界队列**与请求上限，并提供 `/metrics` 和健康检查接口。
- **有意设计成单个管理进程**：先保证正确，再考虑水平扩展。

vLLM 一侧是针对运行时 LoRA API 的代码集成；vLLM 本身尚未打包，用真实适配器进行的单卡冒烟测试（里程碑 W2）也还没有运行。

## Terraform 护栏与 IAM {#infrastructure}

AWS 平台用 Terraform 编写，共 {{fact:tf_resources}} 个资源块，并带有输入校验规则和交叉检查，目前只经过 mock provider 测试验证。

- **网络。** 两个可用区中划分公有、私有应用、私有数据库三类子网，一个 NAT 网关、一个 S3 网关端点和一个私有 Route 53 托管区；安全组之间互相引用。
- **计算。** 启动模板强制使用 IMDSv2 和加密磁盘；不开放 SSH（改用 SSM），所有实例都没有公网 IP。后端伸缩组跟随启动模板的默认版本，因此发布时只需要替换镜像。
- **数据。** RDS PostgreSQL、S3（开启版本控制、禁止公开访问、只允许 TLS）以及带死信队列的 SQS，全部使用 KMS 加密。
- **运维。** 日志组、告警、监控看板、VPC 流日志、月度预算和成本异常告警。

设计笔记中已经由 Terraform 落实的 IAM 不变量：

- `iam:PassRole` 只存在于部署角色中。
- 只有发布角色可以修改启动模板。
- 运行时角色只信任 EC2。
- 训练角色只能读取自己的回调令牌，永远读不到数据库凭证。

还有一条不变量（允许后端按标签清理失控的 GPU 实例）已经设计，但尚未实现。

## 测试与当前状态 {#testing}

共有{{fact:tests}} 个自动化测试函数，全部基于本地替身运行：后端有 PostgreSQL 集成测试和本地端到端测试脚本；worker 与适配器管理服务使用严格模式的 mypy 和 Ruff；契约测试覆盖了那些无效示例；Terraform 有 mock provider 测试，并配置了 TFLint 与 Trivy。前端通过 lint、类型检查和生产构建来验证。

从未运行过的部分：在 AWS 上执行 Terraform plan 或 apply、Packer 构建、GitHub 工作流、GPU 训练，以及用真实适配器运行的 vLLM 推理。

**一处已知的不一致。** 发布工作流会拒绝指向 `$Default` 或 `$Latest` 版本的启动模板，并使用静态访问密钥；而 Terraform 让后端伸缩组指向 `$Default`，并提供了 OIDC 角色。如果针对 Terraform 创建的伸缩组运行，这个工作流会因自己的安全检查而失败。第一次发布之前必须先解决这个问题。
