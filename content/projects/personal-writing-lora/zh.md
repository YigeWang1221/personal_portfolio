## 从个人写作训练到适配器推理 {#problem}

我开发了一个用个人写作语料训练 LoRA、并在对话界面中使用适配器的平台。我设计产品流程、API、数据模型和 AWS 基础设施，再连接训练队列、GPU worker 与 vLLM 推理链路。

核心设计将训练任务与对话请求的生命周期分开。训练生成版本化的适配器并写入对象存储，推理层则在用户选择对应写作风格时加载适配器。

## 产品模型与组件契约 {#planning}

我先将写作流程拆成项目、对话、风格和版本。线框图确定工作区与草稿面板，ER 设计将这些概念连接到数据库。

随后，我用 OpenAPI 和 JSON Schema 定义产品 API，以及后端、训练 worker 与推理层之间的接口。请求 ID、命名错误码和后端生成的版本号为组件提供统一的表达方式。下方的早期线框图与 ER 草图展示了产品结构的形成过程。

## 数据库归属与 GPU 容量管理 {#decisions}

### worker 通过后端回传结果 {#decision-callback}

我将数据库访问集中在产品后端。训练 worker 从 SQS 接收任务，通过带认证的回调返回进度与结果。这样，数据库凭据由一个组件持有，每台训练实例也不需要单独建立数据库连接。回调契约定义 worker 与后端共用的内容格式和认证方式。

### Auto Scaling 管理实例容量 {#decision-lifecycle}

我将容量管理交给 Auto Scaling 组。队列积压触发扩容，worker 在训练期间保护自己的实例，完成后解除保护，再由伸缩策略回收容量。worker 负责执行任务，AWS Auto Scaling 负责实例生命周期。

## 将个人写作连接到对话生成 {#validation}

我在 AWS 上用自己的文字运行训练与推理链路。GPU worker 生成适配器，vLLM 加载它用于对话生成，将产品中的风格版本、实际训练产物和推理时选择的适配器连接起来。

## 当前架构 {#architecture}

- **产品。** Next.js 应用（严格模式 TypeScript、App Router）调用 FastAPI 后端，后端按 router → service → repository 分层。PostgreSQL 中有 {{fact:tables}} 张由 Alembic 迁移管理的表，状态字段由 CHECK 约束保护。会话使用 HttpOnly Cookie 和不透明令牌，数据库里只保存令牌的 SHA-256 哈希。
- **训练任务交接。** 提交训练任务时，同一个事务里写入一条发件箱记录，再由分发器把它送进 SQS。GPU worker 认领任务，用 QLoRA 微调，并把适配器发布到 S3。
- **推理。** 适配器管理服务位于 vLLM 的运行时 LoRA API 之前，负责加载、卸载和缓存适配器，并代理对话和流式请求。

## 至少一次投递下的安全任务交接 {#job-handoff}

SQS 保证消息至少投递一次，GPU 实例也可能在任务中途消失。设计同时假定这两种情况：

- **发件箱。** 后端在同一个事务里记录任务和它的发件箱记录，所以在保存任务和入队之间崩溃，也不会丢失任务。重复投递由下游处理。
- **每个风格版本只有一个任务标识**，重新入队的工作会被识别为同一个任务。
- **用条件写入认领。** worker 通过 S3 条件写入认领任务，所以即使两个 worker 收到同一条消息，也不会都去训练。
- **租约心跳。** 训练期间，worker 不断延长消息的可见性超时；一旦失去租约就停止工作。
- **最后才删除。** 只有后端确认收到结果后才删除消息。回调重试发送完全相同的字节，后端可以据此去重。
- **制品完整性。** 每个适配器写入按用户、任务和制品版本划分的不可变目录，附带 manifest 和每个文件的 SHA-256 哈希。`READY` 标记最后写入，适配器以原子方式移入缓存；系统不会在用户不知情时退回基座模型。

## 队列驱动的 GPU 训练 {#scale-from-zero}

训练队列为空时，Auto Scaling 组保持零台实例。伸缩策略根据每台运行中实例对应的可见消息数，为排队任务增加容量。worker 领取消息，在训练期间保护自己的实例，并在任务完成后解除保护。

训练需求以独立任务到达，因此我选择由队列驱动容量。GPU 实例跟随排队工作变化，产品后端负责记录与分发任务。

## 适配器加载与缓存管理 {#serving}

我在 vLLM 的运行时 LoRA API 前加入适配器管理服务，负责加载、卸载适配器，代理对话与流式请求，并管理有容量限制的缓存。

同一适配器的并发请求共用一次下载。管理服务在加载前检查文件哈希与 `READY` 标记，以原子方式将文件移入缓存，并保护请求正在使用的适配器。LRU 淘汰作用于空闲适配器；容量被占用时，服务返回明确的资源响应。这些规则在管理进程中协调下载、缓存归属与模型使用。

## AWS 基础设施与组件角色 {#infrastructure}

我用 Terraform 定义平台，共 {{fact:tf_resources}} 个资源块。网络分为公有、应用和数据库子网，安全组通过组件引用连接应用、数据库与 GPU 服务。

启动模板配置加密磁盘与 IMDSv2，实例访问使用 SSM。RDS PostgreSQL 保存产品数据，S3 保存数据集与适配器，SQS 传递训练任务并配有死信队列，KMS 为数据服务提供加密。

IAM 与组件职责对应：部署角色传递角色，发布角色写入启动模板，运行时角色信任 EC2。训练角色读取自己的回调密钥，数据库凭据由后端持有。

## 版本化训练产物 {#next}

每个适配器按用户、任务和产物版本发布。manifest 记录文件哈希，worker 在文件发布结束后写入 `READY`。推理层通过这套结构，将用户选定的风格版本解析为具体产物。
