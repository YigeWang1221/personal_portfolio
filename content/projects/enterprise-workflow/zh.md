## 从业务需求到我的实现 {#scenario}

食物救助需要捐赠方、检验员、救助站和司机协作。在团队中，我将这些职责转化为领域模型、工作队列与按角色分派的界面，实现持久化和应用主框架，并参与工作流界面开发。

设计要回答的问题是：如何把这段描述变成对象——有哪些对象、每个对象负责什么，以及工作如何在彼此看不到对方界面的人之间流转。

## 从需求到对象 {#domain-model}

这个模型为上面描述中的每一项职责找到唯一的归属：谁拥有哪些工作，谁把工作交给谁。

- **Network（网络）**是用户登录的单位。它持有各个企业、用户账号，以及跨企业共享的两个队列：检验队列和仓库队列。
- **Enterprise（企业）**把同一类组织归在一起（食品、检验、救助网络、志愿者）。它继承自组织类，所以企业也可以拥有自己的账号和队列。
- **Organization（组织）**拥有一个工作队列和一份用户账号目录，并声明自己支持哪些角色。
- **User account（用户账号）**只对应一个角色，并有一个个人队列。
- **Role（角色）**只做一件事：`createWorkArea()` 为该角色构建工作界面。登录界面在所选网络中完成认证后调用这个方法，因此不需要对角色类型做任何分支判断。
- **Work request（工作请求）**带有发送方、接收方和状态。食品请求、配送请求和需求请求都继承自它；配送请求另有任务状态和指派的司机。

整个设计靠两个抽象支撑。一是角色上的多态取代了分派表：新增一类用户，只需新增一个角色类，登录逻辑不用改。二是队列是界面之间唯一的接缝：每个界面读取一个队列，修改拿到的请求，再放进下一个队列，界面之间从不互相调用。

有一个选择我会保留，也有一个我会修改。把司机的进行中队列和已完成队列放在司机角色里，让"这位司机是否空闲"变成一行代码的判断。但请求自身的 `status` 和配送的 `taskStatus` 是两个自由文本字段，同一个对象可能一个字段写着 `Pending`，另一个写着 `Delivered`。

## 一份捐赠的完整流程 {#workflow}

下面是代码实际实现的路径，状态值即代码写入的字符串。

| 步骤 | 角色 | 代码做了什么 |
|---|---|---|
| 捐赠 | 食品提供方 | 创建食品条目和一条状态为 `Pending` 的请求，并把同一个请求对象放进所在组织的队列、捐赠方自己的队列和网络的检验队列 |
| 检验 | 检验员 | 批准时把食品标记为 `accepted` 和 `stored`，并把请求从检验队列移到仓库队列；拒绝时只从检验队列中移除 |
| 求助 | 受助者 | 在救助网络的收集组织中创建一条状态为 `Pending` 的需求请求 |
| 匹配 | 救助站助理 | 把仓库中的一份食品与一条待处理需求配对，生成配送任务（`UnPick`）；需求变为 `Matched`，食品变为 `Assigned` |
| 调度 | 任务调度员 | 只接受仍为 `UnPick` 的任务，指派司机，把任务设为 `Waiting to be picked up`，并把司机标记为 `busy` |
| 配送 | 司机 | 先标记 `Picked up`，再标记 `Delivered`；食品变为 `donated`，任务从司机的进行中队列移到已完成队列 |

## 设计取舍 {#tradeoffs}

- **队列共享对象。** 请求在队列之间不做拷贝，同一个对象同时存在于多个队列中。这样各个界面无需同步就能保持一致，但一个界面上的修改会立刻在所有地方生效，而且没有任何记录说明是谁改的。
- **业务规则写在界面里。** "只有未分配的任务才能调度"这条规则写在任务调度员的按钮事件里，而不是模型方法中。没有服务层，规则难以测试，也容易被绕过。
- **持久化的是整张对象图。** 嵌入式 db4o 数据库在用户登出或关闭窗口时保存整个系统对象，启动时再载入；文件为空时自动生成种子数据。没有需要迁移的表结构，但把数据库文件提交到 git 引起了合并冲突。
- **一次扩展的实际代价。** 新增一类请求（比如卫生用品）需要一个新的请求子类，以及一个 `createWorkArea()` 返回对应界面的新角色，登录逻辑不变。但每个列出工作的界面都靠 `instanceof` 判断和字符串比较来筛选，所以每个需要显示新请求的界面都得修改，而且编译器帮不上忙。

## 局限与改进方向 {#limits}

- **状态规则不在模型里。** 司机可以不标记"已取货"就直接标记"已送达"；被拒绝的捐赠只是离开了检验队列，捐赠方自己的列表永远看不到结果。
- **已送达的食品会重新出现。** 没有任何代码把已送达的食品从仓库队列中移除，而匹配列表只隐藏标记为 `Assigned` 的食品，所以配送完成后，这份食品又会显示为可用。
- **没有自动化测试。**
- **下一步：** 把状态规则移入模型，用带合法转换的枚举表示；把队列之间的移动封装为模型方法；首次运行时由种子数据生成数据库，而不是把数据库文件提交进仓库。
