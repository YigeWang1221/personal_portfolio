## 系统概览 {#system}

FoodShelter 用来协调食物救助：捐赠方提供食物，检验员检查新鲜度，救助网络管理无家可归的服务对象及其需求，任务调度员分配配送任务，志愿者和司机负责配送，管理员维护组织结构，分析员查看运营指标。每个角色登录后进入自己的工作区，工作以请求的形式在共享队列中跨组织流转。

## 领域模型 {#domain-model}

模型遵循严格的层级：系统包含多个网络，网络下有企业（四种类型），企业下有组织（七种类型），组织中是用户账号，每个账号对应十四种角色类中的一种。工作被建模为请求（配送、食品、需求），放在网络所拥有的工作队列中，因此一个组织可以把请求交给另一个组织，而各个界面之间不必互相依赖。

持久化使用嵌入式对象数据库 db4o：应用启动时加载整个对象图，关闭窗口时保存；演示数据由 Datafaker 生成。界面用 NetBeans GUI 构建器开发的 Java Swing 实现，代码分为模型、界面和工具三个包。

## 我负责的部分 {#ownership}

这是三人团队项目，我们通过功能分支和 PR 协作（共 {{fact:prs}} 个 PR）。我创建了仓库和 Maven 构建，设计了领域模型（{{fact:model_classes}}模型类以及全部工具类由我创建），并编写了带角色登录的主程序框架。我还与队友一起实现了任务调度、司机配送、食品检验和救助网络工作流。系统中的 JFreeChart 指标看板和 iText PDF 报表由队友完成。

## 收获 {#lessons}

- **把二进制数据库放进 git 是个坑。** 提交 db4o 文件导致了合并冲突；更好的做法是首次运行时从种子数据生成数据库。
- **生成的界面代码很冗长。** GUI 构建器画界面很快，但代码审查很慢。
