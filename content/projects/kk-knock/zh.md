## 将语音想法整理成待办或研究笔记 {#product}

我开发 KK Knock，是为了在不方便打字时留住一闪而过的想法与提醒。我围绕语音流程设计交互，并实现 Android 客户端、后端和管理端。

手机通过 whisper.cpp 转写语音，后端判断文本意图：可执行的安排生成带截止时间的待办，需要展开的想法经过资料研究后生成附来源的笔记。Android 应用将结果保存在本地，用于编辑、搜索和桌面小组件展示。

我将录音和笔记存储放在手机端。采集请求向后端发送文本，已保存笔记的编辑与整理在本地完成。

## 录音与后台处理同时推进 {#iteration}

我将录音与分类、研究分开。转写文本保存后，麦克风即可接收下一次录音，当前任务继续在后台处理。

我通过小组件表达这种分工：后台运行任务时保留可录音的图案，用数量显示排队工作，进度环只表示本地转写。“最近采集”页面集中展示运行中、完成和失败的记录，并提供重试、播放和删除操作。

队列在重试时复用保存的音频或文本，将租约过期的任务重新入队，并通过 WorkManager 安排退避执行。界面将这些操作与采集历史放在一起。

## 持久化采集任务与响应复用 {#reliability}

我在录音开始时为每次采集分配 ID，并在转写、处理和存储过程中沿用。Room 保存任务与进度，WorkManager 通过租约认领排队任务。

转写文本保存前，音频继续保留。转写重试使用音频，分类或研究重试使用文本。本地结果 ID 由账号和采集 ID 派生，因此重新接收结果时会更新同一条记录。

我还实现了以账号和采集 ID 为键的后端缓存，将完成的待办或笔记响应保存 {{fact:idempotency_window}}，后续请求可以读取已有响应。缓存保存返回的内容与来源，转写文本用于处理流程。

## 手机 CPU 上的语音识别 {#asr}

我通过 Android NDK 集成 whisper.cpp，实现按 {{fact:asr_window}} 窗口增量转写，并提供整段文件处理路径。在测试手机的短合成音频上，运行时 ARM64 内核选择将 Small 模型转写耗时从 {{fact:asr_before}} 降至 {{fact:asr_after}}。

我在该设备上比较不同执行路径后选择 CPU：Flash Attention 增加了转写时间，Vulkan 返回 `DeviceLost`。应用通过运行时内核选择使用 ARM64 执行路径。

我加入原生中止补丁，将取消操作传递到转写代码，并在构建时应用到固定版本的 whisper.cpp 源码。语音模型下载采用哈希校验与原子替换。

## Android 界面与桌面小组件 {#validation}

我将采集流程接入 Compose 界面与桌面小组件。录音小组件启动采集，待办小组件展示保存的任务，应用内提供笔记编辑与采集历史查询。用户可以通过项目介绍页下载 Android 应用。

## 架构 {#architecture}

系统分为两半，两者之间有一条严格的数据归属边界。

- **Android 客户端**（Kotlin Multiplatform、Jetpack Compose）拥有所有笔记。只有一个前台服务可以录音。用 NDK 编译的 whisper.cpp 在设备上转写。采集任务在 Room 中的任务队列里流转，由 WorkManager 驱动；结果写入 Room，并显示在桌面小组件上。
- **后端**（FastAPI、异步 SQLAlchemy、PostgreSQL 16）负责账号、个人资料、提示词、用量计量和公告。后端没有笔记表，唯一与采集相关的表就是上面提到的响应缓存。
- **模型处理分阶段执行。** 先判断输入是待办、想法还是无需处理；复杂待办再拆成子任务，想法则进入研究与资料整理。简单待办不需要额外的细化调用。分类、待办细化和研究使用可配置的模型位，调用协议由 URL 决定。
- **React 管理后台**（TypeScript、Vite）管理用户、用量、公告和系统设置，有独立的管理员认证。

## 大模型成本控制 {#cost}

一个免费的消费级 App 调用大模型，必须有硬性上限。每次调用都按服务商、模型和缓存使用情况计量，计数器在数据库中原子递增。

- **默认拒绝。** 价格未知的调用直接拒绝，不做估算。价格调整只影响之后的用量。
- **预算快照。** 每个套餐在每个计费周期都有 AI 成本预算，Free、Lite、Pro 的默认值分别为 {{fact:budgets}}。预算在周期开始时复制进该周期，之后的修改不会影响进行中的周期。周期以每个账号自己的开始日期为锚点。
- **配额与测试例外。** 测试账号不受配额限制，但照样计量。

## 自托管与 AWS 备用方案 {#operations}

**当前部署。** 后端用 Docker Compose 运行在我自己的 Mac mini 上，通过 Cloudflare Tunnel 提供公网访问。PostgreSQL 的数据放在外部卷上；FastAPI 服务以非 root 容器运行，并带健康检查；Nginx 提供管理后台、反向代理 API，是唯一对外暴露的端口。首次运行的初始化程序只会处理空数据库，备份文件以受限权限写入。

**同一个后端的 AWS 部署路径。** 决定自托管之前，我先搭了一条可随时销毁的 AWS 路径。Terraform 创建一个小型 VPC 和一台 EC2 实例，通过 SSM Session Manager 管理，不开放 SSH。CI 流水线测试后端、打包可复现的制品、校验摘要，再通过 GitHub 的 OIDC 联合身份构建 Packer AMI，全程不使用静态 AWS 密钥。两者都在 2026 年 8 月跑通过，包括一次完整的创建、测试、销毁；这条路径作为备用方案保留。

**强制更新。** 后端决定最低支持的 App 版本，旧版本会收到 HTTP 426 和更新提示。诊断日志只记录请求 ID 和耗时，不记录内容。

## 产品与系统设计 {#planning}

我将语音采集的想法落实为交互原型、API 职责与组件分工。手机处理录音、转写和笔记存储，后端处理模型调用、账号与用量，管理端负责应用配置。

这种分工形成了异步采集流程：后端处理上一段文本时，手机可以接收新的录音。
