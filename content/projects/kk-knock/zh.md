## 产品 {#product}

要做的事和冒出来的想法，很少挑你有空的时候出现。KK Knock 就是为这些时刻设计的：刚停好车、一手推着购物车、正在做饭。点一下桌面上的 KK Capture 小组件，说出想法，再点一下结束。App 会把它整理成带截止时间的待办（你说的时间会记成截止时间），或者一条研究过、附有来源的想法；内容不足以整理时，不会生成任何条目。

产品遵循四条原则：

- **在手机上转写。** 语音转文字由 Whisper 在手机上完成，录音不会上传。
- **只发送文字。** 为了分类和研究，只把转写后的文字发送给后端和大模型服务。
- **结果保存在手机上。** 待办和想法存在本地，而不是在线的资料库里。
- **修改只在本地。** 修改、整理和搜索笔记都不会调用大模型。

它刻意不做聊天机器人、项目管理套件或文档编辑器。

## 当前架构 {#architecture}

系统分为两半，数据归属的界线很明确。

- **Android 客户端**（Kotlin Multiplatform、Jetpack Compose）拥有全部内容。只有一个前台服务有权录音；用 NDK 编译的 whisper.cpp 在手机上完成转写。每条捕捉经由 Room 中的任务队列、由 WorkManager 驱动处理，结果写入 Room，并显示在桌面小组件上。
- **后端**（FastAPI、异步 SQLAlchemy、PostgreSQL 16）只负责账号、个人资料、提示词、用量计量和公告。它不保存任何转写文本或结果；与捕捉相关的唯一一张表，是只存响应的幂等（idempotency）缓存。
- **大模型层**与供应商解耦。DeepSeek 模型通过 OpenAI 兼容接口担任分类器，把捕捉判为 TODO、THOUGHT 或 IGNORED；Gemini 结合 Google 搜索为想法做研究。每个槽位根据配置的 URL 选择调用协议。
- **React 管理后台**（TypeScript、Vite）用于管理用户、用量、公告和系统设置，使用独立的管理员认证。

登录时用 Google ID token 换取 App 自己的 JWT，以内部账号 ID 为主体；账号从不按邮箱合并。

## 如何规划 {#planning}

这个项目靠书面决策推进。每个仓库都有写给 AI 编码代理的规则，另有一套共享的项目记忆（项目背景、架构、当前状态和决策日志），让我和 AI 编码代理保持一致。决策日志在大约四周内积累了 {{fact:adrs}} 条记录，每条都写明背景、决策与影响，被取代的决策也会明确标注。

工作按阶段拆分，每个阶段都有自己的文档。端侧转写部分有一份需求文档，明确了硬性的阶段边界和增量窗口的设计。2026 年 9 月的一次功能审查梳理了范围，并确定了后续阶段的待办。

## 关键决策 {#decisions}

| 决策 | 备选方案 | 选择 | 取舍 |
|---|---|---|---|
| 内容存放位置 | 服务器数据库，或只存手机 | 只存手机，服务器不存内容 | 不能跨设备同步；换来更强的隐私和更小的服务端 |
| 语音在哪里转写 | 云端 ASR，或端侧 | 端侧 whisper.cpp | 弱机型上更慢，且需要下载模型；录音不出手机，也没有按分钟计费 |
| 如何加速 ASR | GPU（Vulkan）、NPU、Flash Attention 或 CPU 内核 | CPU，运行时选择 ARM64 内核 | 放弃可能的 GPU 收益；在不同芯片上表现一致 |
| 流式还是分窗 | 逐 token 流式，或增量窗口 | 增量窗口 + 整段转写兜底 | 延迟高于流式；实现更简单、更稳健 |
| 托管方式 | AWS EC2（已搭建并测试），或自有 Mac mini | Mac mini + Docker Compose | 单台主机、家庭网络；没有托管费用，完全自主可控 |
| 防重复 | 不处理、客户端键，或服务端标记 | 客户端捕捉 ID + 服务端响应缓存 | 请求处理中到达的重复请求仍可能被重复计费；不保存任何内容 |
| 大模型供应商 | 单一供应商，或与供应商解耦的槽位 | 按 URL 选择的中立槽位 | 配置项更多；分类和研究可以使用不同供应商 |

## 近似恰好一次的采集链路 {#capture}

一条捕捉要经得起 App 被杀、网络不稳和反复重试，既不能丢失语音，也不能重复入库。为此客户端保留了三层持久化记录：

1. **转写回执。** 只有转写回执安全落盘后，才会删除录音。
2. **提交回执**，记录每一次 HTTP 提交及其响应。
3. **Room 中的任务队列**，用 SQL 认领租约保证同一条捕捉同一时间只有一个 worker 处理。

客户端捕捉 ID 在开始录音时生成，之后不再改变。本地记录使用由账号和这个 ID 派生出的稳定 ID；服务端按账号和捕捉 ID 缓存每次响应，保留 {{fact:idempotency_window}}。响应丢失后的重试会直接回放缓存结果，不会再次调用大模型。重试按阶段区分，遵守 `429 Retry-After`，并采用退避重试和保留上限。

**已知缺口。** 如果重复请求在第一次请求仍在处理时到达，响应缓存拦不住它，可能被重复计费。计划在服务端增加"处理中"标记。

## 端侧语音识别 {#asr}

转写按 {{fact:asr_window}} 的增量窗口进行，并以整段转写兜底。这是分窗口的批量处理，不是逐 token 的流式识别。

性能优化是在一台测试手机上、用短合成音频测的，没有控制温度，因此这些数字说明的是趋势，而不是通用基准：

- **运行时选择 ARM64 内核**后，Small 模型的单段转写耗时由 {{fact:asr_before}} 降至 {{fact:asr_after}}。
- **测试后放弃的方案：** Flash Attention 反而让转写变慢；六线程运行不稳定；手机 GPU 上的 Vulkan 出现 `DeviceLost` 错误。App 保持纯 CPU 运行，在不同芯片上的表现一致。
- **即时取消。** 为 whisper.cpp 加入原生中止补丁后，取消尚未开始的转写所需时间由 {{fact:cancel_before}} 变为 {{fact:cancel_after}}；转写过程中发出的取消在 {{fact:cancel_mid_run}} 内返回。

中止补丁在构建时以覆盖层方式应用，打补丁前先校验锚点，因此内置的 whisper.cpp 源码保持固定版本并可校验哈希。语音模型下载时校验 SHA，再以原子替换的方式生效。

## 大模型成本治理 {#cost}

一款免费的消费级 App 调用大模型，必须有硬性上限。每次调用都按供应商、模型和缓存命中情况计量，计数在数据库中原子递增。

- **未知即拒绝。** 遇到价格未知的调用直接拒绝，而不是估算；价格调整只影响之后的用量。
- **预算快照。** 每个套餐都有按计费周期计算的 AI 成本预算，Free、Lite、Pro 的默认值分别为 {{fact:budgets}}。周期开始时预算会复制进该周期，之后的调整不会改变正在进行的周期。计费周期按每个账号自己的起始日期计算。
- **配额与测试例外。** 测试账号不受配额限制，但仍然计量。

## 自托管、测试与运维 {#operations}

**自托管试运行。** 后端运行在自有的 Mac mini 上，使用 Docker Compose：PostgreSQL 的数据放在外部数据卷；FastAPI 服务以非 root 容器运行，并带健康检查；Nginx 提供管理后台、反向代理 API，是唯一对外发布的端口。首次启动的初始化程序只作用于空数据库，备份文件使用受限权限。该部署在 2026 年 9 月通过验收，覆盖 ARM64 构建、健康检查、管理后台路由、未认证访问的边界、重建容器后数据保留，以及备份。

**同一后端的 AWS 路径。** 在选定自托管之前，我先搭建了一条可随时销毁的 AWS 路径：用 Terraform 创建小型 VPC 和一台 EC2，通过 SSM Session Manager 而不是 SSH 管理；CI 流水线负责测试后端、打包可复现的制品、校验摘要，并通过 GitHub OIDC 联合身份构建 Packer AMI，全程不使用静态 AWS 密钥。两者都在 2026 年 8 月成功运行，其中包括一次完整的创建、测试、销毁流程；这条路径现作为备用方案保留。

**强制更新。** 后端决定最低支持的 App 版本，旧版本会收到 HTTP 426 并提示更新。

**测试。** {{fact:tests}} 个自动化测试用例覆盖后端（含 PostgreSQL 集成测试）、Android 客户端（单元测试、宿主测试和设备测试）以及管理后台。诊断日志只记录请求 ID 和耗时，从不记录内容。

## 局限与下一步 {#limits}

- **只有一台测试设备。** 目前的 Android 验收只覆盖一部手机（OnePlus，Android 16）。
- **尚未公开发布。** 产品介绍页已经上线，第一个公开的 Android 版本仍在准备中。
- **公网 HTTPS 待验收。** Mac mini 前面的 Cloudflare Tunnel 已经配置，但还没有公网验收记录。
- **iOS** 目前只有项目骨架，应用商店计费暂缓。
- **下一步：** 测量延迟分布（结束录音 → 转写完成、转写完成 → 结果返回）和每条捕捉的成本，增加第二台测试设备，录一段简短的演示视频，并用服务端标记补上请求处理中的重复缺口。
